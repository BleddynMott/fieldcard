## Short spec (26 Nov)

**What G-02 builds** (scope signed in G-00 R8): five mini-games from one date seed, every number in one config file: the five events (Stop, Count, Repeat, Pair, Sort), Spot it, Pour the sand as the Read of the day, Claim it, and the Scorecard with Hands, Hunch, Flag and the share text. Rules, copy and names as in `4-spec.md` (run folder) and `design/DESIGN.md`; screens as in `design/directions/b-final-run.html`.

**Not in G-02:** the Hot Seat (G-04b), Pick, Fix and Find (G-04a), teams and the Mirror Duel (G-04c), Sunday (G-04d), any server (G-03). Every comparison is against the simulated crowd, made from the card's seed and labelled "simulated crowd" on every reveal.

**Order (the plan's gate).** 1. Stack, config, card seed, harness, Stop end to end, preview URL. 2. His word on Stop against `design/reference/1-event-stop-mid-play.png`, taken to "matches". 3. Only then Count, Repeat, Pair, Sort. 4. Spot it, Pour the sand, Claim it, Scorecard, share. 5. Harness over all of it, CI green, design-check green. 6. The phone step: one whole card, three screens against the three references. 7. K05 review, then the pull request.

**Files.** `config/games.json` (every number), `src/lib/` (card seed, generators, crowd, scoring, device store), `src/` screens in Svelte, `tests/` (harness and unit tests), `scripts/task-checks.sh` (the task's checks, called by `ci-checks.sh`).

## Rulings

- R1 (mine): stack is Vite + Svelte 5 + TypeScript as a static single-page app, Vitest for tests, npm with `package-lock.json`. No SvelteKit: no routes and no server until G-03.
- R2 (mine): the one config file is `config/games.json`. It holds the launch date, each event's parameters and weekday steps, the doors' bands, the five boxes per event, scoring, and the simulated crowd's size. Code holds no tunable number. `design-check.sh` check 3 reads its `games` array.
- R3 (mine): the harness is a Vitest suite over the real generators and scoring (`tests/harness.test.ts`), not the skill's `puzzle_harness.py`, so the check runs the code a player runs. It keeps that script's checks (deterministic, no repeat, a spread of difficulty, share text clean and short) and adds the plan's (scores in range, one attempt a day) and the spec's (Pair has exactly one identical pair, Sort blobs differ by at least 3% in area, Count between 3 and 30, no repeat within 365 days).
- R4 (mine): until G-04a the Read of the day is Pour the sand every day, on the event the weekday table gives that day, which is never the doors' event.
- R5 (mine): with no Hot Seat in G-02, Hunch is out of 90 (Spot it 10, Pour the sand 80), as the spec does for a skipped seat.
- R6 (mine): one attempt a day is held on the device, keyed by card number; G-03 adds the server's hold.
- R7 (mine): sizes the mock-up wrote literally (bib, chip, lane, marker) get named tokens in `design/tokens.css`; build code never writes them. Coordinates inside an SVG `viewBox` are drawing geometry, not size values.
- R8 (mine, his to change): card #1 is the day the preview first goes up; the launch date is one value in the config and moves to the real launch day before launch.
- R9 (mine): `dist/` (built output, git-ignored) is skipped by `design-check.sh`, as `node_modules/` is.
- R10 (mine): look durations (taps, reveals) are tokens in `tokens.css`; game timings that set difficulty (how fast the marker sweeps, the pause between goes) are numbers in `config/games.json`, which the plan says holds every number.
